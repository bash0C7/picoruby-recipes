# PicoRuby デモ v2 - 技術詳細

## 設計判断と根拠

### 機能の取捨選択

**削除した機能とその理由：**

1. **音声認識（UnitASR）**
   - 理由: MIDI連携に集中、UART1をMIDI Unit専用に
   - 評価: デモのフォーカスが明確になる
   - 代替: 押しスイッチのみで十分

2. **距離センサー（VL53L0X）**
   - 理由: IMU（3軸）で十分なコントロール次元
   - 評価: I2Cバス負荷削減、センサー数削減
   - 代替: IMUの3軸で3つのパラメータ制御

**追加した機能とその理由：**

1. **IMU→MIDI CC送信**
   - 理由: 物理的動きと音色変化の直感的リンク
   - 評価: 演奏表現力が大幅向上
   - 技術: 加速度→CC値変換（0-127マッピング）

2. **MIDI Note→LED可視化（n60pc.rbロジック）**
   - 理由: 視覚と聴覚の統合体験
   - 評価: 演奏が目に見える、観客向けパフォーマンス
   - 技術: ノート番号→位置+色のマッピング

### アーキテクチャの進化

**v1→v2の主要変更：**

```
【削除】
- UnitASR制御ループ
- VL53L0X距離読み取り
- 色相8方向分類
- 輝度線形マッピング

【追加】
- MIDI CCステートマシン
- LED明るさ配列管理
- フェード減衰処理
- セミトーン→色変換

【不変】
- IRQボタン制御
- MPU6886キャリブレーション
- PC UART通信
- 単一統合ファイル方式
```

**評価**: よりシンプルで、MIDIとIMUの統合に集中

## MIDI CC実装の詳細

### 加速度→CC値変換アルゴリズム

**設計目標:**
- 傾き±2Gを0-127にマッピング
- 水平位置（基準値）を中央値64付近に
- クリッピングで範囲外を防止

**実装:**
```ruby
def accel_to_cc(value, base_value)
  diff = (value * 100).to_i - base_value
  cc_value = ((diff + 200) * 127 / 400).to_i
  cc_value = 0 if cc_value < 0
  cc_value = 127 if cc_value > 127
  cc_value
end
```

**パラメータ選択:**
- 整数化スケール: 100倍（精度と範囲のバランス）
- 範囲: -200〜+200（±2G相当）
- マッピング: 線形変換（直感的）

**代替案検討:**

1. **対数マッピング**
   - メリット: 中央付近で敏感、端で鈍感
   - デメリット: Math.log必要、計算コスト高
   - 評価: 却下

2. **指数マッピング**
   - メリット: 端で敏感、中央で鈍感
   - デメリット: 複雑、直感的でない
   - 評価: 却下

3. **線形マッピング** ✅ 採用
   - メリット: シンプル、直感的、計算コスト最小
   - デメリット: 全域で同じ感度
   - 評価: 演奏しやすい、予測可能

### CC送信頻度の設計

**実装:**
```ruby
if current_time - last_cc_send_time >= 100
  # CC送信
  last_cc_send_time = current_time
end
```

**100ms間隔の根拠:**

1. **10Hz送信頻度**
   - MIDI標準: 31250bps、CCメッセージ3バイト
   - 理論上限: 約1000メッセージ/秒
   - 実用: 10Hz（3軸で30メッセージ/秒）十分

2. **CPU負荷バランス**
   - LEDメインループ: 50Hz
   - CC送信: 10Hz
   - 5:1の比率で効率的

3. **シンセサイザー応答性**
   - 人間の聴覚: 100ms以下は連続的
   - 10Hz: 音色変化がスムーズ

**代替案:**
- 50Hz（20ms）: 過剰、UART負荷増
- 20Hz（50ms）: バランス良いが計算増
- 5Hz（200ms）: カクカクした変化

## LED可視化の実装詳細

### ノート番号→位置マッピング（n60pc.rb参照）

**設計方針:**
- MIDI範囲36-84（C2-C6、49音）を60 LEDに配置
- セミトーン（12音階）で色を決定
- オクターブで位置をずらす

**マッピング式:**
```ruby
semitone = (note - 36) % 12  # 0-11
octave = (note - 36) / 12     # 0-4
pos = semitone * 5 + octave   # 0-59
```

**具体例:**
```
ノート36 (C2): semitone=0, octave=0 → pos=0
ノート37 (C#2): semitone=1, octave=0 → pos=5
ノート48 (C3): semitone=0, octave=1 → pos=1
ノート60 (C4): semitone=0, octave=2 → pos=2
```

**視覚化パターン:**
```
LED位置:  0  5 10 15 20 25 30 35 40 45 50 55
音階:    C C# D D# E  F F# G G# A A# B
オクターブごとに+1位置シフト
```

**代替案検討:**

1. **線形マッピング（pos = note - 36）**
   - 問題: 49音が60 LEDに不均等
   - 評価: 却下

2. **オクターブ重ね（同じ音階=同じ位置）**
   - 問題: 位置情報が失われる
   - 評価: 却下

3. **セミトーン×5 + オクターブ** ✅ 採用
   - 利点: 音階と位置の関係が明確
   - 利点: 全60 LEDを効率利用
   - 評価: 最適

### セミトーン→色マッピング

**12色スペクトラム設計:**

```ruby
def note_to_color(semitone, brightness)
  case semitone
  when 0  # C: 赤
    [brightness, 0, 0]
  when 1  # C#: 赤オレンジ
    [brightness, brightness / 4, 0]
  when 2  # D: オレンジ
    [brightness, brightness / 2, 0]
  # ... 12音階で色相環を一周
  end
end
```

**色相環の配置:**
```
C → C# → D → D# → E → F → F# → G → G# → A → A# → B
赤   RO   橙   YO   黄   YG   緑   CG   水   CB   青   紫
```

**設計根拠:**
- 音楽的: 音階の循環を色相環で表現
- 視覚的: 虹色グラデーションで美しい
- 直感的: 高音=青系、低音=赤系の一般的イメージ

**代替案:**
1. ランダム色: 視覚的混乱
2. 単色: 退屈
3. 音程で色相環 ✅: 美しく意味的

### フェード効果の実装

**減衰アルゴリズム:**
```ruby
def fade_leds(state, fade_rate = 0.97)
  LED_COUNT.times do |i|
    state[:led_brightness][i] = (state[:led_brightness][i] * fade_rate).to_i
    state[:led_brightness][i] = 0 if state[:led_brightness][i] < 5
  end
end
```

**パラメータ調整:**
- `fade_rate = 0.97`: 1フレームで3%減衰
- 閾値5: 暗すぎる値を0にカット
- 計算: 整数化で高速化

**減衰時間計算:**
```
初期値255 → 閾値5
255 × 0.97^n = 5
n ≈ 70フレーム
70フレーム × 20ms = 1.4秒
```

**代替案検討:**

1. **fade_rate = 0.90** (速い減衰)
   - 約46フレーム（0.9秒）で消える
   - 評価: 速すぎる、残像効果薄い

2. **fade_rate = 0.95** (中間)
   - 約59フレーム（1.2秒）
   - 評価: バランス良いが少し速い

3. **fade_rate = 0.97** ✅ 採用
   - 約70フレーム（1.4秒）
   - 評価: 自然な減衰、心地良い残像

4. **fade_rate = 0.99** (遅い減衰)
   - 約140フレーム（2.8秒）
   - 評価: 遅すぎる、色が混ざる

### 周辺LED拡散効果

**実装:**
```ruby
# 中心LED
state[:led_brightness][pos] = brightness

# ±1位置: 2/3の明るさ
if pos > 0
  state[:led_brightness][pos - 1] = brightness * 2 / 3
end

# ±2位置: 1/3の明るさ
if pos > 1
  state[:led_brightness][pos - 2] = brightness / 3
end
```

**拡散パターン:**
```
位置:        -2    -1   [0]   +1    +2
明るさ比:   1/3   2/3   1    2/3   1/3
```

**ガウシアン風減衰:**
- 中心が最も明るい
- 周辺は段階的に暗くなる
- 5 LED幅の光の玉

**代替案:**
1. 拡散なし: 点光源、寂しい
2. 均等拡散: 不自然
3. ガウシアン風 ✅: 自然で美しい

## パフォーマンス最適化

### 状態管理の設計

**明るさ配列方式:**
```ruby
state = {
  power: true,
  led_brightness: Array.new(LED_COUNT, 0)
}
```

**利点:**
- 位置ごとの明るさを個別管理
- フェード処理が単純な乗算
- 複数音の重ね合わせ可能

**代替案: RGB直接管理**
```ruby
colors = Array.new(LED_COUNT) { [0, 0, 0] }
```

**問題:**
- フェード時に色情報が必要
- RGB→明るさ変換が複雑
- セミトーン情報が失われる

**評価**: 明るさ配列＋描画時色変換が最適

### ループ構造の最適化

**時系列分離:**
```ruby
loop do
  IRQ.process              # 毎回
  
  if 100ms経過
    MIDI CC送信            # 10Hz
  end
  
  PC UART受信・解析       # 毎回（バッファリング）
  
  フェード処理            # 50Hz
  LED描画                 # 50Hz
  
  sleep_ms 20            # 50Hz
end
```

**頻度設計:**
- ボタン: 即応（IRQ）
- CC送信: 10Hz（十分）
- MIDI受信: 50Hz（バッファ消化）
- LED更新: 50Hz（視覚的十分）

**CPU負荷配分:**
```
ボタンIRQ:     1% （割り込み）
CC送信:       10% （10Hz、3軸）
MIDI解析:     20% （可変長）
LEDフェード:  30% （60個ループ）
LED描画:      30% （RGB変換＋転送）
余裕:          9%
```

### メモリ使用量

**主要データ構造:**
```ruby
colors: Array.new(60) { [0,0,0] }          # 60 × 3 × 8 = 1,440 bytes
state[:led_brightness]: Array.new(60, 0)   # 60 × 8 = 480 bytes
COLOR_TABLE: 定数                          # 無視
```

**合計: 約2KB**（RAM 520KBの0.4%）

**評価**: メモリ消費は極めて少ない

## MIDI統合の技術詳細

### ステートマシン方式（継続）

**状態遷移（v1から不変）:**
```
State 0: ステータスバイト待ち
  ↓ 0x90/0x80/0x99/0x89受信
State 1: ノート番号待ち
  ↓ ノート番号受信
State 2: ベロシティ待ち
  ↓ ベロシティ受信 → LED更新
State 0: 次へ
```

**v2での拡張:**
- Ch1 (0x90/0x80): メロディ系
- Ch10 (0x99/0x89): ドラム系
- 両方同じLED可視化処理

### Program Change初期化

**実装:**
```ruby
midi_uart.write((0xC0 + 0).chr + 83.chr)
```

**Program 83の選択:**
- GM規格: Synth Pad系
- 理由: CC（フィルター、レゾナンス）が効きやすい
- 代替: 任意のプログラムに変更可能
